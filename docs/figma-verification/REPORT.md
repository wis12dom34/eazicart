# EaziCart Figma implementation and verification

The existing Customer routes and shared navigation were updated for the purchase flow and related screens below. Seller routes remain separate. **This is not a claim of complete or pixel-perfect implementation of the whole Figma file.** Several production services and metadata are missing, and typography differences remain.

## Evidence and scope

Figma file: https://www.figma.com/design/747q8npBh3lvQTo9HPKYY8

Every row below has a Figma reference, an application capture at **430 × 932**, a side-by-side comparison (Figma left, application right), a 50% overlay and a 4× amplified RGB difference. Application widths **360, 375, 390 and 440 × 932** were also captured for every row and checked for document-level horizontal overflow. Filenames use `<screen>-app-<width>.png`; the 430px capture is `<screen>-app.png`. These are browser sandbox fixtures, not evidence of production backend capability.

Inter 400/500/600/700 is locally packaged, pinned to @fontsource/inter 4.5.15 (Inter 3.019). Figma's exact font binary/build was unavailable; antialiasing and some glyph widths/baselines still differ. The difference images visibly retain these discrepancies. No zero-difference or pixel-perfect threshold is asserted. Device safe areas are implemented with CSS environment insets, but physical iOS safe areas and native keyboard behavior were not tested. The keyboard check uses a reduced browser viewport of 375 × 520.

## Validation

Production Next build, TypeScript, ESLint and 11 existing unit tests pass. The production browser harness verifies the sandbox flow, state recovery, route identity, persistence, keyboard focus and all five viewport widths. [Interaction results](captures/interaction-results.json) include the actual sandbox writes and tested assertions. [Comparison metrics](captures/comparison-metrics.json) are diagnostic RGB differences, not an acceptance threshold.

No real payments, deployment, telephone calls or customer messages occurred. Payment initialization redirects only to the local sandbox callback. Order creation and verification assertions preserve the same order ID. Non-Nike products are explicitly checked to retain their own detail links and copy.

The exact Figma assets are checked into `apps/web/public/figma/`. Primary Nike node `8:54` deliberately retains its blank gallery; alternate `226:50` was inspected but not substituted. Chat `62:2` was inspected, but there is no existing Chat route/service or validated association for its conversation/order card. Chat remains disabled; its messages and order links were not fabricated. Unsupported Wallet, Map, tabs and inventory actions are also explicit rather than connected to unrelated routes.

Existing authentication, generic loading/error/review states, address CRUD forms, Seller screens and other Figma screens are outside this verified set. They must not be inferred complete from the shared navigation changes. Lower Home evidence is additionally available in `home-full-app.png`, `home-scroll-reference.png` and `home-lower-comparison.png`; Explore and Profile lower content needs a separate full-scroll visual pass before full-body fidelity can be claimed.

## Reproduce

```sh
pnpm install --frozen-lockfile
pnpm --filter @eazicart/web build
pnpm --filter @eazicart/web typecheck
pnpm --filter @eazicart/web lint
pnpm --filter @eazicart/web test
pnpm exec playwright install chromium
node docs/figma-verification/verify.cjs
python docs/figma-verification/compare.py
```

Python comparison generation requires Pillow. A custom Chromium executable may be supplied with `EAZICART_CHROMIUM_PATH`. The browser harness starts and closes its own local production server, intercepts backend requests, and writes the captures into this folder. Figma reference exports are retained in `captures/references/` where SVG was available; other reference screenshots are PNG.
